## 实时提问、截图与问答库

- 面试官还在说话时可按 **Ctrl+Enter**：已有可回答的转写会立即提交，无需等 final；如果只有半句话，界面会提示已记住按键，等同题内容补全。超时后可检查转写并再次提交。面试官补充条件后再次按键更新；“重答”可重新回答同一版本。候选人接话或开始回答不会清除待答问题。
- **Ctrl+H** 和 **Ctrl+?**（或 Ctrl+Shift+Enter）都会识别当前截图任务。算法题保留解法和代码；Vibe Coding 显示任务边界、方案和可复制的分步提示词。顶部“屏幕模式”可为当前题选择自动、普通解题或 Vibe Coding。“复制当前提示词”只复制文字；下一张截图要继续同一题时先点“下次截图继续本题”，换题时点“结束本题”。
- 在 **设置 → 项目资料 → 项目问答库** 导入 JSON 或预览编辑器内容，核对新增、更新与冲突后应用。可搜索试问、编辑、启停、删除、导出，以及切换短答/详答。安全命中会显示“问答库命中”并原文返回，无需 API Key；未完整匹配时走模型路径。格式见 [问答格式说明](cue-qa-format.md)。
- 选择“导入问答文件”后，先查看预览中的项目、数量和冲突；展开题目可以核对答案，点击“确认导入”后等待成功和新增/更新/保留数量。取消、关闭或按 Escape 会退出未提交的预览，不修改资料。提交时暂不可取消；如果显示结果尚未确认，先关闭预览并刷新材料状态，再决定是否重新预览。试问输入框与列表搜索分开，项目可按名称选择。
- 当前问题区域会保留尚未完整识别的场景前文并可滚动。在“管理已回答的片段”中，可以把自己已经回答的已确认转写片段移出本次提问，也可点“恢复待答”。请保留未答问题和后续问题需要的场景条件；目前系统不会自动判断本人发言是否已经完整回答了问题。
- 在 **设置 → 风格 → 回答风格** 写自己的语气、结构和长度要求。填写后，默认的编号、短标签和 260 字口述展示上限不再覆盖该风格；实际回答仍须满足题意并依据资料，不能编造本人经历。
- 在 **设置 → 风格 → 实时上下文** 选择最近 1–3 轮。默认最多使用当前题及前两轮面试官问题，独立题不带旧题；默认不参考本场本人语音。需要模型参考时可主动打开“参考我实际回答”，仍受所选轮次限制。

更详细的模式边界和操作示例见 [实时交互与问答库](CUE_2026-10-27_实时交互与问答库.md)。

设置、问答预览和窗口内下拉列表使用 CUE 的受保护窗口；系统文件选择器是独立的系统界面。具体录屏方式的验证范围见 [捕获保护说明](capture-protection.md)。

## Windows 最快启动

安装 Git 和 Node.js 22.12.0 或更新版本。在 PowerShell 中进入你已有的 cue 仓库：

```powershell
cd "D:\你的目录\cue"
git status
git pull --ff-only
npm ci
npm start
```

如果尚未下载仓库，先运行 `git clone https://github.com/Astrea-296111/cue.git`，然后 `cd cue`。如果 `git status` 显示本地修改，先备份或提交自己的改动；不要用 `reset --hard` 清掉配置或代码。`--ff-only` 不能完成时，保留现场并处理分支分歧。

启动后按以下顺序配置：

1. 打开右下角设置，进入“简历与岗位”，在“个人资料工作区”点击“导入个人资料文件…”，选择私人交付包里的 **workspace.json**。
2. 预览应显示 **194 张卡、2 个岗位、9 个来源**。确认后，状态应包含 `cae / arclight`、资料版本和当前岗位。
3. 在“当前目标岗位”选择 AI 算法或 Java 基础安全。到“模型与 API”填写本机模型配置，点击“测试当前服务连接”，再点设置右上角“完成”。
4. 输入“介绍一下简历第一个项目，你负责什么？”，点击发送。确认命中 CAE；继续问“第二个项目如何控制上下文？”确认切到 Arclight。

首次导入后可以直接使用 `npm start`。个人资料保存在本机应用数据目录，重启会保留。仅 `git pull` 不会下载你的私人简历，也不会改变已安装的 EXE。

## 源码、安装版和版本确认

`npm start` 启动当前仓库源码；桌面快捷方式通常启动以前安装的应用。这是两个启动位置。更新源码后，旧 EXE 的文件内容不会自动改变。

需要新的 Windows 应用时，在更新后的仓库运行：

```powershell
npm run pack:win
# 便携 EXE：
npm run dist:win
# 安装程序：
npm run dist:win:installer
```

结果在 `dist`。打包需要下载构建资源；没有签名证书的包可能显示 Windows 发布者提示。不要将 API 密钥、私人工作区或本机数据复制进安装包。

在设置中点击“导出脱敏诊断…”，查看 JSON 的 `build.buildCommit`、`build.sourceDirty` 和 `build.identitySource`。它们表示正在运行的源码/包身份。打包脚本会生成构建信息；不要只看相同的应用版本号判断代码是否更新。

## 需要导入什么

| 文件 | 内容 | 处理方式 |
| --- | --- | --- |
| 私人交付包 `workspace.json` | 简历、两岗位、194 张事实/问答/叙事卡、来源与边界 | 在“简历与岗位 → 个人资料工作区”单文件导入一次 |
| `facts.json` | 同一成品的独立事实索引 | 已导入 workspace 后不用再导入 |
| `manifest.json`、`merge-log.json` | 摘要、数量与迁移日志 | 留作核对 |
| `materials/bundle.json` | 两个项目的公开源码索引 | 已随源码和安装包内置，无需手动导入 |
| 附件原始 seed JSON | 编译输入 | 不能直接当成 CUE 事实包导入 |

源码固定版本为 Arclight `528704eb373f637830640b3fefcc5cbc95f23a78` 和 CAE `c50dd29d1b1981e299d2ce4821e0a1ef745aa48e`。本轮修正了输入校验包的误排除规则，重建 Java 泛型方法、try-with-resources 和 Python 多行函数边界，并补充显式导入函数/别名及模块策略表；调用关系只在当前项目可明确解析的范围内展开。当前公开索引有 **345 个文件、2519 个片段**，原文件字节与 Git blob/hash 可核对。

需要更新上游时才运行 `npm run sync:sources` 和 `npm run compile:materials`。这会检查公开仓库并更新 source-lock；更新版本后还须核对导航符号、事实引用和评测，不能混用不同提交的实现。

命令行导入的等价路径：

```powershell
npm run prepare:personal -- --workspace "D:\Cue私人资料\workspace.json"
npm run start:personal
```

它把成品保存为仓库内被 Git 忽略的 `.cue-private/workspace.json`，再通过正常材料服务安装。兼容旧版的 `--resume … --facts … --jd …` 仍可用，但 facts 必须是校验过的 CUE 格式。普通使用不需要再次转换本次 seed。

## 升级、重复导入与岗位切换

v1→v2 保留稳定卡 ID、旧来源和原版本；新格式增加问答关系、指标口径、叙事范围和源码核查元数据。资料数量超限会明确报错，不静默截掉尾部卡片。

重复导入同一 revision 不覆盖你后来编辑的简历、JD 或事实。导入新版本时，未改过的字段和卡更新，后续本地修改默认保留；材料代次冲突应重新预览。旧资料备份在应用数据目录的 `personal-workspace-backups`，统一材料服务另保留上一版事实与源码快照。需要恢复材料时，设置的“项目材料”页提供“恢复上一版材料”；该按钮只恢复事实与源码，不撤销简历、岗位及模型设置。个人资料备份是恢复用记录，不是可直接重新导入的 `workspace.json`。

两个岗位分别保存 JD，切换时保存当前岗位的编辑并载入另一个 JD。切换会取消旧回答，下一次请求使用冻结的新岗位配置；项目事实保持不变。AI 岗优先突出 Agent/上下文/评测，Java 岗优先突出可靠受理、事务、幂等和权限边界。JD 中的 KMS、供应链世界模型或后训练要求，不会自动变成候选人的既有经历。

## 本机模型设置

GitHub Secrets 供 Actions 使用，不会自动出现在你的本机应用。请在本机设置里填自己的凭据；不要尝试从 GitHub 导出明文密钥。

| 服务 | 应用配置 | 本轮使用的文本模型 |
| --- | --- | --- |
| Qwen | “自定义”，官方协议选择 DashScope；中国区常用 base URL 为 `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.8-flash` |
| DeepSeek | “DeepSeek”；常用 base URL 为 `https://api.deepseek.com` | `deepseek-flash` |

模型 ID 和区域应与你的服务账户一致；没有访问权限时，连接测试会显示错误，不自动猜另一个付费模型。填写“快速模型”和“深度思考”两个模型 ID 字段，核对“模型窗口”，然后点击“测试当前服务连接”。连接成功只证明接口能返回正文，不能证明项目问答质量合格。

极速模式默认使用快速模型和已准备的内存证据，不串行调用额外分类模型。标准模式有更大的证据预算。官方支持时可以显式关闭思考；协议不支持时界面会说明能力未知，不假称服务端已经关闭。

普通口述和代码题分别有输出上限，默认 1800 / 6000 token。代码上限最高 16384，且问题、必要发言、证据和预留输出总和仍须放进模型窗口。遇到长度截断时，检查报告的 finish reason 和窗口设置，不能把半段代码当成完成。

## 两个人的声音怎样进入系统

点击顶部监听按钮或按 `Ctrl+R`，允许麦克风；按平台提示选择通话软件/屏幕的系统音频并勾选共享音频。候选人麦克风为 `you`，面试官系统声为 `them`。建议使用耳机，避免外放从麦克风再次进入。

Qwen ASR 在“音频与转写”配置，可复用官方 DashScope 的自定义服务密钥；也可以选其他已支持的云 ASR 或本地 Whisper。本地模式需要先下载对应模型和运行时，不以文本模型密钥是否有效推断 ASR 权限。

GitHub Actions 中可在仓库 **Settings → Secrets and variables → Actions → New repository secret** 添加 `QWEN_ASR_API_KEY`，填入有阿里云百炼流式语音识别权限的密钥。已有 `QWEN_API_KEY` 也可被测试工作流复用，但仍需确认它有语音权限。区域或型号与默认值不同时，可在同一页面的 Variables 设置 `QWEN_ASR_MODEL` 和 `QWEN_ASR_WEBSOCKET_URL`；不确定时先使用默认值。通过 Actions 的 **Real Mandarin scenario audio** 手动运行中文合成语音测试，结果在运行记录的 artifact 中。GitHub Secrets 供 Actions 使用，不会自动配置你电脑上的 CUE：本机仍需在应用设置中填写语音服务凭据。不要将密钥写进代码、配置文件或聊天。

角色映射是输入线索：低置信或跨通道回声可能标为待确认。在“简历与岗位 → 核对实际发言的角色和文字”查看最近记录，选择“我 / 面试官 / 待确认”，修改识别文字，点击“保存纠正”。保留原文和修订关系，不把真实口误偷偷改成从未说错。

只有真人事件和你明确修订的发言进入已说账本。AI 显示过的建议单独保存，不能因为显示过就当作你已经照读。断线重发、重复 final 和 interim 修订按事件 ID/revision 处理。

软件音频 fixture、真实云 ASR、真实麦克风/声卡是三个验证层次。本轮实际执行状态见评测和捕获验证文档；虚拟显示器上的文本回放不证明你的声卡设置正常。

文本事件回放可以验证重复、修订、乱序、角色不明、回声及取消后的迟到事件。它不能证明 ASR 在静音、两人同时说话、半句被打断或断线重连时仍能正确识别。双通道软件音频结果也只覆盖所用片段及云端识别链路；这些故障场景与物理设备的执行状态应分别查真实评测报告，未执行项不能视为通过。

## 日常回答、改口与停止

| 操作 | 默认入口 |
| --- | --- |
| 输入问题 | 底部输入框，发送按钮 |
| 根据面试官问题提供口述 | “如何回答”或 `Ctrl+Enter` |
| 屏幕与问题一起分析 | 对应按钮或 `Ctrl+Shift+Enter`；保留 `Ctrl+?` 兼容快捷键 |
| 上下文解题 | `Ctrl+L` |
| 截屏代码题 | “截屏”或 `Ctrl+H` |
| 停止当前回答 | “停止生成” |
| 修改当前问题 / 重答 | “本次回答”旁“编辑 / 重答” |
| 隐藏/恢复整个窗口 | `Ctrl+P` |
| 开始/停止录音 | `Ctrl+R`，也可用设置的监听快捷键 |
| 鼠标穿透 | `Ctrl+Shift+I`，再次按恢复交互 |
| 移动窗口 | `Ctrl+Shift+方向键` |
| 新会话 | 对话记录中的“清空记录” |

全局快捷键可能被其他软件占用；注册失败会给诊断信息。macOS 使用 Command 对应 Control 的跨平台绑定，具体平台捕获边界见捕获验证矩阵。

普通单问主卡先给结论、一处机制及取舍/验证，通常 2–4 句；多子问按题目覆盖，代码题保留代码。长场景题使用独立的较高输出预算，最多4096 token，并受“长场景 / 代码输出上限”限制；普通短答继续使用口述上限。较长的普通回答可以展开/收起完整正文。“反问”需要主动触发，不自动混进当前口述。

默认情况下，本人语音不会进入实时答题上下文，也不会自动纠正刚才的口误。需要参考本人发言时，请先开启“参考我实际回答”；可在记录中修订说话人和文字。项目资料仍可作为独立来源使用。

“停止生成”会取消旧请求和迟到 UI 更新，已发生的真人发言保留。新会话清空已说状态、指代和建议历史，个人资料与密钥保留。切换项目隔离旧项目结论；明确的一般知识插问暂停项目事实，“回到刚才那个任务”可以回到已建立的线程。

## 全程面试 TXT 留档

默认开启“简历与岗位 → 自动保存面试对话为 TXT”。点击“打开面试记录文件夹”即可找到文件；每次开始新会话会新建 TXT，清空界面、重启应用或更新源码不会删除旧文件。

文件包含面试官、本人和说话人待确认的已确认转写，手动修改角色或文字时追加修订记录。手动输入的问题、CUE 建议分别标注，建议不会冒充本人已经说出的话。记录持续追加，不受界面只保留最近部分对话的限制；保存的是文字，不是原始录音。正常退出前会等待待写内容落盘。实际遇到磁盘空间或权限错误时，设置页显示保存失败，当前转写仍在界面可见。

复盘或请 Codex 优化时，可以从这个文件夹选取对应 TXT，并说明当时用了哪个模型及遇到的问题。记录留在本机，不会自动上传。关闭自动保存只暂停后续留档，已有文件仍保留。

## 资料没有细节时怎样回答

事实卡未覆盖当前问题时，CUE 会继续按工程经验给出具体方案、步骤和取舍，用“我会这样处理”承接。遇到冷门技术，先用一句话说明作用，再举有输入、处理、结果的小例子，避免只说“不知道”或“资料不足”。例子用于解释方案，已知项目事实和你实际说过的限定仍优先。

## 8 个导入验收问题

| 问题或对话 | 应有范围 |
| --- | --- |
| 简历第一个项目是什么，你负责哪部分？ | CAE；后端职责，不冒充求解算法作者 |
| 第二个项目如何处理长上下文？ | Arclight；工具输出、预算、压缩与恢复 |
| 281 ms 是求解完成时间吗？ | 持久受理 P95；保留 300 批次、5 并发、每批50 Case 的口径 |
| 确认丢失后，重试会不会再启动进程？ | 同执行身份、核验远端事实；不推导全链路恰好一次 |
| 默认关闭本人语音后说“CAE 用 Kafka”，再问无关问题 | 本人发言不进入该实时请求或检索；项目资料仍按范围使用 |
| 开启参考本人语音并修订为 RabbitMQ 后追问 | 只在所选近邻窗口内参考修订，不把旧口误当作事实 |
| Arclight 的 worktree 能隔离共享任务文件吗？ | 工作目录隔离与共享文件并发分开，不虚构 CAS/事务 ACK |
| 分别切换两个岗位，要求30秒自我介绍 | 当前身份+相关项目；事实不变，不把 JD 变成已做经历 |

可以在诊断中核对资料 revision、项目 ID、当前 JD、实际模型和请求问题。问题命中了卡不等于最终每句都正确，仍需对照回答及引用。

## 答案慢或没有反应

先确认当前回答目标，再看状态：没有转写 final 时检查录音权限、系统音频是否共享和 ASR 状态；已得到问题但未发请求时检查材料导入和准备状态；已发送而没有正文时检查模型、思考设置、网络、配额及 provider 错误。

诊断中的 `prepareMs` 是本地准备，`firstContentMs` 是请求到首个非空正文，`triggerToFirstContentMs` 包含本地准备，`triggerToFirstUsefulSentenceMs` 为首句启发式。reasoning、空白和状态提示均不计模型首字。DOM/双 RAF 确认也不等于屏幕像素实际呈现。

429/认证失败先处理账户配置；网络中断可停止再重答。不要为提速关闭源码或捕获保护；先看证据是否就绪及具体慢阶段。明确“资料不足”的答案也要检查是否导错 workspace、停用了事实卡或正在使用旧 EXE。

遇到模型问题，用“导出脱敏诊断…”保留问题 ID、实际回答、版本、资料 revision 和实际发言，再检查内容后分享。导出会去除配置密钥和常见电话/邮箱，但正文仍可能含项目私密信息，文件不会自动上传。

## 自动测试与真实报告

日常运行 `npm test`，只执行显式核心清单。Electron 核心 UI 为 `npm run test:ui`，Windows 原生保护为 `npm run test:protection -- --native-only`。这些不是模型质量认证。

已配置 GitHub 凭据和仓库 Secrets 后，一条命令可以触发、上传密文、等待、下载并在本地解密：

```powershell
npm run eval:remote -- --payload ".cue-private\workspace.json" --scenarios ".cue-private\task-2026-10-24\data\multiturn_scenarios.json" --profile smoke --judge --judge-reference ".cue-private\workspace.json" --output-dir ".cue-private\results\smoke"
```

完整 deep 为 20 会话 × 4 问 × 2 模型 × 3 重复：

```powershell
npm run eval:remote -- --payload ".cue-private\workspace.json" --scenarios ".cue-private\task-2026-10-24\data\multiturn_scenarios.json" --profile deep --concurrency 1 --judge --judge-reference ".cue-private\workspace.json" --output-dir ".cue-private\results\deep"
# 终端意外退出后，复用原响应密钥恢复，避免重复推理：
npm run eval:remote -- --resume ".cue-private\results\deep\resume.json"
```

场景文件来自私人交付包，不在公开仓库重复提供。报告在各分片 `reports` 和合并报告目录；本地 `local-key.json` 仅用于解密，丢失后不能恢复原密文回答，禁止提交或上传该文件。状态含义：`failed` 有阻断/质量问题；`needs-review` 有评分冲突或证据疑点；`unverified` 未完成双模型或必要验证；Mock 只证明链路。

冻结旧版比较使用 `--application baseline --source-snapshot baseline`。评测器源码可以更新，旧应用模块和 Prompt 仍固定到9898a05。不要用修复后的应用冒充旧基线，也不要把原资料/兼容子集/完整新资料混成同条件对照。

对照各组的 `--judge-reference` 必须指向同一份最新权威成品，核对报告中的 `judgeReferenceSha256`。它是独立的裁判输入，不会作为生产资料导入或发送给被测模型；旧资料的USER标签不自动证明新增的历史细节。实际个人导入通过正常预览/确认接口，revision及9份来源清单完整保留。临时评测目录可以持久化私人资料来验证真实存储，API密钥仍只留在内存，清理后不留运行目录；完整报告须私下保存。

## 窗口捕获保护

应用保留隐藏创建、显示前保护、Windows 原生0x11回读、失败隐藏、恢复/焦点/移动/缩放/穿透后的复核。新增资料预览和纠正入口留在同一受保护窗口；新选择列表采用窗口内 DOM，避免独立原生 popup。

`--native-only` 证明句柄与原生标志，不证明 OBS、腾讯会议或远程软件实际捕获到的像素。平台/捕获模式的通过、失败和未实测状态见 [capture-validation.md](capture-validation.md)。不要承诺所有软件都无法捕获，也不要为测试截图新增关闭保护的开关。
