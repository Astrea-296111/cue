# 项目材料、连续追问与证据诊断

事实 JSON、源码文件夹和 ZIP 现在共用一套导入预览。设置中选择导入方式，再选择材料；先检查项目、增改删列表和旧/新卡片差异，最后点击“确认应用此预览”。默认“合并更新”保留未涉及的卡片；“替换本次项目”仅替换输入包声明的项目；“替换全部事实”会列出删除项，源码仍保留。每张更新卡可选保留旧卡。文件之间存在不同版本时必须选择版本；项目映射有歧义时必须选择 canonical ID。

JSON 文件名不限。文件夹和 ZIP 自动识别 `interview/facts.json`、`project-fact-packs.json` 和 `CUE_最终项目事实.json`；额外相对路径可在设置里逐行填写。普通 `package.json` 继续作为源码配置。事实文件走独立的 2MiB 校验通道，在普通源码 320KiB 限额之前读取，并从源码切片中排除。保留现有源码路径、敏感文件与解压限制；组合导入拒绝非法事实、路径越界和 ZIP 符号链接。

预览绑定主进程读到的内容，提交不会重新读取已改变的原文件。另一个窗口先提交后，旧预览会提示版本变化，需要重新选择材料。用户的嵌入来源按原始 UTF-8 校验哈希；没有嵌入来源的旧包仍可导入。溯源路径不会触发任意文件读取，也不会将来源全文展开到目录或模型请求。

“重载事实资料”读取有效材料快照；“导入 / 重新扫描源码”重新选择原目录，准备新的预览。每个项目显示事实卡、源码文件和片段数。事实单独更新保留源码快照。“恢复上一版材料”同时恢复上一代事实、源码和项目映射；内置默认卡始终随安装包保留，未写入用户的个人叙述。

## 独立开关

- 项目事实卡：控制极速、标准两种模式的结构化事实；默认启用。
- 极速源码：关闭或仅使用已就绪源码；回答键不等待源码检索。
- 标准源码：关闭、仅使用已就绪源码或有界检索。
- 旧手动项目资料：独立保留、可停用。没有结构化元数据的长文本不会被自动删除；可能和新卡片冲突，界面会提示这一边界。

旧 `instantRagPolicy=off` 迁移为极速源码关闭，事实仍独立启用。迁移提示可关闭，关闭状态与显式禁用事实都持久保存。旧实验 `rag-off` 映射为源码关闭；`context-only` 保留其标准模型行为。

同一项目的姓名、团队、职责和时间类短追问继承当前项目。显式名称与纠正优先于默认选择器。“Redis 过期策略 → 只有五种吗”继续通用话题，“回到刚才那个项目”恢复暂停的项目线程。未知项目和比较后的歧义追问会请求简短澄清。只有事实的项目没有源码 scope，避免空范围检索所有项目。

## 保存与恢复

材料保存在 Electron `userData/cue-materials/`，不写入源码仓库。`current.json` 指向同一 generation 下的事实、源码、registry，并记录受控相对路径及 SHA-256。所有文件写入、校验完成后，用同目录临时指针 rename 发布；Windows 占用失败有限重试，不先删除有效指针。

首次迁移读取旧事实覆盖层及 v1/v2 源码索引，保留 `.pre-materials.bak`。之后只读材料 provider。进程内请求绑定不可变版本；发布后取消旧请求、预取和缓存，迟到 token 不进入新回答。无效外部指针继续使用有效内存快照并提示；启动时当前代损坏则验证上一代，二者都坏时保留文件并报错，不静默覆盖。快照不自动清理，至少保留上一代。

故障注入测试覆盖事实、源码、registry 写入、发布前和发布后退出。已验证的是进程中断恢复；没有模拟真实断电、文件系统缓存或所有 Windows 占用行为，不宣称断电持久性保证。

## 每次回答的诊断

诊断抽屉显示项目、解析原因、generation、事实/源码 revision、候选/进入上下文/实际发送的卡片与源码 ID，以及裁剪理由。最终发送列表在 SDK 序列化后再次核对。原因包括 `facts-disabled`、`source-rag-off`、`general-question`、`unresolved-project`、`no-matching-card`、`source-not-ready`、`scope-mismatch`、`budget-pruned` 和 `revision-changed`。

实现题保留就绪源码的位置；人数、职责、时间题优先对应用户卡。超过预算的补充卡可以整张跳过并补位。当前问题、否定条件、子问和用户风格不被裁成另一道题。USER/source-claim 可按资料范围口述；新设计、参考故事、测试数据仍遵守原状态与来源边界。旧 AI 回答只用于指代，不是事实。

指标继续区分触发到发送、首个非空模型正文和近似绘制时间。reasoning、心跳、空白与本地要点预览不算首字。诊断不记录密钥、简历或材料正文；来源全文只在主动展开参考依据时查看。流式回答保留换行，结束后安全渲染 `<ol><li>`，支持单换行编号、续行、代码围栏和非 1 起始编号。

## 本地验收和性能复现

公共 CI 使用合成材料。最终 109 卡属于本机资料，不进入 Git：

```sh
npm run verify:materials -- --facts /path/to/final.json \
  --cae-source /path/to/cae-job-platform --arclight-source /path/to/Arclight \
  --output /tmp/materials-acceptance.json
npm run benchmark:materials -- --facts /path/to/final.json --pipeline \
  --baseline-ref 1852c165abc7f8cda4f1f523e7374355ad27aee6 \
  --output /tmp/materials-benchmark.json
npm test
DISPLAY=:99 npm run test:ui -- --no-sandbox
```

验收使用隔离临时 userData，不改用户桌面安装的资料；结束清理临时快照。检查实际 SDK 请求中的卡片 ID、禁止串项目、状态原文保留、两种模式和关闭源码后的零检索。性能脚本预热 100 次，100 个不同问题轮转，25/109/160 卡各至少 1000 次；含源码有/无、比较、通用题和追问。基线选择器从指定 Git ref 读取，在同一进程和输入下比较；基线不支持所有短追问，其空结果数单独披露。没有私有路径时使用 109 张合成卡。

`--pipeline` 测真实应用入口到流式 mock SDK 的发送准备时间，不能代表在线模型首字或答案正确率。本环境没有配置可用的真实服务密钥，未执行在线 20—30 题人工评估。独立报告导入、迁移、冷启动与热路径分位数，不给单元测试加入硬件耗时门槛。

最终兼容检查补充：只有事实项目、没有源码且源码关闭时，标准模式仍可按 canonical 身份使用已绑定的旧手动资料；关闭手动资料后不再发送。该路径只给纯文本选择器传递虚拟身份，未调用源码检索；相关 19 项运行时、简历和标准问答回归通过。
