# 窗口录屏保护的范围与验证

参考仓库 `harden2961119413-sys/cue` 的 HEAD 为 `06e26ff`。该版本和当前版本均使用 Electron 33.2.1 的 `setContentProtection(true)`，近期快捷键、界面和上下文功能没有删除此调用。该 API 请求操作系统限制窗口内容捕获，不会让进程、窗口或权限使用对操作系统不可见。

本次加固：

- 主窗口和 Cue 自身的权限引导窗口以隐藏状态创建，在显示前请求保护；Ctrl+P 恢复和应用内授权提示也复用同一请求流程。
- 源码正常启动与打包版均始终请求保护。旧环境变量 `CUE_NO_PROTECT` 不再控制实际启动链的保护，避免遗留的 `1`、`0`、`false` 等配置让保护被跳过。
- Electron 调用抛出异常时记录错误、隐藏窗口并阻止主动显示，不弹错误对话框。原有鼠标、拖动和键盘功能保留。

Electron 的此接口没有返回底层保护是否成功的结果。调用完成只能证明已请求保护，不能证明某个录屏软件实际遵守了保护。

## 平台限制

Windows 10 内部版本 19041 起，Electron 使用 `WDA_EXCLUDEFROMCAPTURE` 请求从兼容的捕获结果中排除窗口；旧版 Windows 使用旧保护行为，捕获结果可能显示黑色窗口区域。macOS 使用窗口共享限制，Linux 没有此接口提供的内容保护保证。

显示器、窗口、游戏、显卡驱动等捕获方式可能使用不同路径。不能通过应用层接口保证所有录屏方式都无法捕获，也不能绕过系统权限或隐藏进程。本次不修改操作系统权限、录屏软件或进程身份。
