# 2026-10-26 使用与验收

1. 启动应用，打开设置并导入`materials/personal/workspace.json`。查看项目/卡片数量和替换预览，再确认；不要把新卡叠加到旧矛盾卡上。来源与实验设计可直接打开明文阅读。
2. 主界面选择`Arclight`、`cae`、`八股`。一次只选一个，按钮可键盘聚焦，选中状态会持久化。岗位JD、模型服务和极速/标准独立选择。
3. 手动输入或识别到面试官问题后点“如何回答”。默认短答，点“展开细节”才发起详细回答。截图/编写代码保留独立代码预算。
4. 范围切换会取消旧生成、清理旧检索及项目待答推断。原始真人记录保留；新会话只清对话状态，保留材料和用户选择。问题点名另一项目时显示切换提示，不悄悄混入其事实。
5. 看参考面板核对指标单位、样本和来源。九项指标独立检索；用户简历数字不等于本次实测。局部口述声明只用于承接，不会把AI建议当成自己已说的话。
6. 公开结果从`evaluation/index.md`进入。每条答案与请求、证据、裁判一起保留；本地截句和供应商length截断均不能把失败变为通过。

开发验证：`npm test`；Linux虚拟显示下`DISPLAY=:99 npm run test:ui -- --no-sandbox`。原受保护Electron窗口继续使用，没有新增未保护窗口。Windows原生捕获保护、真实麦克风和声卡需在Windows设备上独立实测；本次Linux离线/UI测试不能替代。

真实模型：先12条烟测，查看原文并修正，再冻结新的run-id跑260条。API失败、长度失败、裁判无效JSON、语义错误分别保留。任何没有真实调用的结果都不能作为通过。不得因只保留漂亮答案而覆盖旧run目录。

历史194卡及解密密钥丢失的旧结果为unavailable，不能补造历史回答。当前129卡与原始上传来源可追踪；源码核查与项目历史指标声明是不同证据。

最新一轮面试补充：当前可导入工作区保留上述129卡并增加3张源码卡，共132卡。长期记忆是编码偏好/纠正反馈/项目知识/参考资料，工具错误是ToolResult返回；不得改写成购物画像库或统一业务错误码中心。原始inputSchema与本地Pydantic校验分开核查。

语音回放使用每个原输出点之前的完整真人记录前缀，按发言ID及revision合并，排除所有旧AI建议；原文、修订和角色不确定性仍保存。指代冻结完整的temperature/top-p或稀疏/稠密召回实体。跨声道短时间包含重复只标记疑似串音，不能据此肯定本人经历；可人工修改说话人。

Actions公开评测支持`full`（原67题双模型各2次）、`replay`（41历史题各2次）、`baseline-replay`（原代码、同一新资料与真人前缀）、`material-control`（同一新代码、旧公开事实包）、`multiturn`（6组连续会话）和`latest`（最新17次口述与2道新编SQL题）。最新TXT没有原截图，9次屏幕建议只能审查旧输出，不能算原屏幕题复测；两道SQL是明确新编的隔离SQLite回归，不执行模型Python程序。

Windows CI已通过原生capture exclusion探针和安装包构建；`--native-only`未进行实际桌面抓图，也未验证真实声卡、麦克风、系统录音和端到端ASR。Linux Electron离线UI验收已通过。首次模型内容超时保持原始失败，不重新生成替换。
