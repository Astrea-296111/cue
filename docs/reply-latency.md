# 实时回答首字延迟

本次针对 Windows 用户反馈的「同一个 qwen-flash，在当前 Cue 中要等 5–7 秒才出现首字」。参考版本为 `harden2961119413-sys/cue@06e26ff`，改动前当前版本为 `da986d1`。本次没有访问用户的私有模型密钥，也没有将转写速度或服务商性能认定为故障原因。

## 发现与改动

1. **全量哈希向量计算阻塞主进程。** `ProjectSearch.add()` 曾为所有导入片段同步计算向量；查询即使传入 `hashFallback: false` 也仍扫描全部向量，最后才丢弃结果。现在按需计算向量并缓存，关闭哈希检索时完全不计算、不扫描。快速模式的正式检索与后台预取都使用关键词、路径、符号等候选；已完成的真实语义预取继续复用。深度模式和独立检索调用保留哈希回退。
2. **语义等待落在首字前。** 正式请求原先最多等待语义 worker 100ms。快速模式只使用已经完成且身份完全匹配的语义预取，未完成时立即走基础检索；不会额外等待 worker。深度模式保留有上限的语义等待、取消和超时回退。
3. **qwen-flash 缺少明确快速请求参数。** 参考版本按所有 Qwen 名称发送 `reasoning_effort: none`，当前版本原先只为少数原始 Qwen3 型号设置思考开关。现在官方 DashScope 的 `qwen-flash`（含日期版本）在快速模式明确发送 `enable_thinking: false`，深度模式发送 `true`，用户显式配置优先。不对未知网关或未知模型猜测兼容参数；原始混合 Qwen3 还可使用其文档支持的 `/no_think` 指令。字段缺失不能单独证明用户原来的请求实际执行了隐藏推理。
4. **实时 SDK 请求存在隐式重试。** OpenAI SDK 默认允许两次重试，可能叠加退避和多次推理等待。快速实时回答现在对 OpenAI 兼容、Azure、Anthropic 请求关闭自动重试，失败直接报告，用户可主动重试。深度和总结任务保留默认行为。
5. **追问历史与重复提示增加读取量。** 快速口述默认历史预算改为普通追问 2,400 字、显式指代 3,600 字；完整对话仍留在内存，显式配置的预算和屏幕代码任务保留原行为。当前完整问题、所有子问、约束和选中的项目证据保留；不再把当前问题重复写入问题清单和场景区。输出上限按题型保留，未通过减少完整代码空间缩短首字时间。
6. **截图与本地上下文原先串行。** 现在并行启动，截图仍必须成功，取消和过期请求仍不能发布结果。

界面原先已逐块显示模型正文，没有发现等待整篇回答完成再显示的缓冲逻辑。仍保留这一行为，并验证了真实 SDK 的首块正文能在响应结束前交付。

## 离线前后对比

使用相同依赖、相同 Linux 主机、相同合成资料和固定 SDK 传输，分别执行 `da986d1` 的源码快照与本次源码。[原始测量及检索摘要](benchmarks/reply-latency-2026-10-20.json) 保留完整样本。

| 场景 | 改动前本地准备 | 改动后本地准备 |
| --- | ---: | ---: |
| 4,000 个源码片段，首次查询 | 1,060.68ms | 362.39ms |
| 同资料，后续查询 | 127.05ms | 29.19ms |
| 不返回结果的语义 worker，后续两次查询 | 107.92 / 105.84ms | 5.98 / 5.28ms |

这些样本只证明本地开销变化，不是实际 qwen-flash 首字时间，也不构成「5–7 秒已经降到某个固定值」的实机承诺。冷启动样本数量很小，不能当作 P95；不同机器、项目规模和问题会改变结果。

60 道固定合成检索题：typed / fast 候选来源召回率均为 100%，提示词内证据覆盖率为 74.3% / 75.7%，多问完整覆盖率均为 60%，跨项目资料混入均为 0。不同模式使用独立的来源上下文缓存。18 步实际入口、Ctrl+Enter 和 SDK 消息回放均路由正确，没有跨项目资料、旧项目建议或界面展示但未发给 SDK 的来源。检索覆盖不是最终回答准确率，测试没有调用真实 LLM。

## 使用与诊断

重新安装依赖、打包并运行新的 Windows 版本；只拉取源码不会更新旧 EXE。面试口述优先关闭「深度思考」，使用快速模型 `qwen-flash`。可在源码目录运行：

```sh
node scripts/benchmark-reply-latency.cjs --large-index
node --test test/realtime-latency.test.js test/provider-capabilities.test.js
node scripts/evaluate-rag.js --out /tmp/cue-rag.json
```

Windows 下可将最后一个输出路径改为系统临时目录。基准和检索评测不下载模型，也不调用在线 LLM。

新日志按同一 `requestId` 关联，只记录耗时、计数、模型名和思考控制字段，不记录请求正文、密钥或原始思考：

- `[latency][prompt]`：`prepareMs`、`contextMs`、`screenMs`、历史大小和实际请求预算。截图和上下文耗时会重叠，不能相加当作总耗时。
- `[latency][model]`：最终 SDK 请求中的 `enableThinking`、`reasoningEffort`、`thinkingBudget` 和实时重试策略；qwen-flash 官方快速请求应为 `enableThinking: false`。
- `[latency][reply]`：`llmFirstTokenMs`、`providerResponseMs`、`firstProviderEventMs`、`reasoningStartedMs`、`reasoningToFirstTokenMs`。思考事件到正文之间的间隔包含传输等等待，不能解读为精确的模型计算时长。
- `[latency][ui]`：`tokenToPaintAckMs` 衡量正文到界面绘制确认的间隔。

转写来源支持同一问题由多个 final 拼接的情况。`finalAgeAtRequestMs` 含用户决定按快捷键的时间；VAD 时间是检测到的语音边界，不等于物理停声瞬间。

当前云端验证了请求构造、检索、实际 SDK 的本地流式传输和 Electron 界面。用户机器上完整 5–7 秒的阶段分布仍需用新版日志确认；未把未测量的剩余时间归因于服务商或语音识别。
