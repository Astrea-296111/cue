# CUE 多轮测试场景

20 个会话各有 4 次待测回答，共 80 题；每个模型每次重复都从独立会话开始。候选人发言是固定的真实发言回放输入，即使与 CUE 刚给的建议不同，也必须按这里输入。参考断言仅供评测器与裁判读取，不应作为标准答案注入被测模型。

## s01 CAE 背景到 Kafka 口误

岗位 java_security；模式 instant；标签 project, spoken-error, no-followup-keyword, correction

**面试官：** 介绍一下简历上的第一个项目，你具体负责哪些部分？

**应覆盖：** 按简历顺序命中CAE；职责与求解器算法分开

**不得主张：** 把Arclight当第一个项目；编真人团队人数

**候选人实际发言：** 我主要做后端任务链路，提交之后用 Kafka 派发，求解不是我写的。

**面试官：** Kafka 的分区键怎么选，为什么这么选？

**应覆盖：** 承接候选人Kafka口误；先短句纠正实际RabbitMQ；Kafka分区键仅作为替代方案

**不得主张：** 声称CAE已用Kafka；编Kafka分区数

**候选人实际发言：** 对，我说错了，实际是 RabbitMQ，想表达的是把提交和执行解耦。

**面试官：** 那你这里为什么不直接发 HTTP 到计算节点？

**应覆盖：** 沿用已纠正RabbitMQ；区分可靠受理与实际远程调用；不重复无必要纠错

**不得主张：** 完全没有HTTP；再次机械道歉纠正已修正内容

**候选人实际发言：** 远程节点还是有 HTTP 交互，但入口不应该一直等求解结束。

**面试官：** 如果 HTTP 超时，但对面已经启动了怎么办？

**应覆盖：** 稳定执行身份；超时不等于未执行；核验远端事实与重投幂等

**不得主张：** 超时立即创建新进程；全链路恰好一次

## s02 Outbox 不能推出全链路 exactly once

岗位 java_security；模式 standard；标签 project, wrong-guarantee, database, validation

**面试官：** Outbox 的事务边界在哪？

**应覆盖：** 业务与Outbox同事务；发布不应把长外部等待塞在业务事务内

**不得主张：** Outbox彻底消除重投

**候选人实际发言：** 我把业务和Outbox放一起，因此整条链路就exactly-once了。

**面试官：** broker confirm 到了，写 SENT 前进程挂了呢？

**应覆盖：** 纠正exactly-once表述；说明confirm到落库的重投窗口；消费及远端幂等仍需要

**不得主张：** confirm证明最终业务完成

**候选人实际发言：** 那应该会重新发布，但同身份受理不会重复创建。

**面试官：** 唯一索引在这里解决什么，事务隔离级别能代替它吗？

**应覆盖：** 解释并发先查后插竞争；持久唯一性与事务边界；不臆造实际隔离级别

**不得主张：** 隔离级别天然消灭所有重复副作用

**候选人实际发言：** 唯一约束是落库兜底，单纯先查有没有还会有竞争。

**面试官：** 请给一套能证伪你方案的故障测试。

**应覆盖：** 提交后断网；confirm与SENT之间崩溃；消费提交与ACK之间崩溃；进程数与账本核验

**不得主张：** 只看HTTP200；声称本轮已经执行这些故障

## s03 UNKNOWN 资源释放与不确定性

岗位 java_security；模式 instant；标签 project, resources, contradiction, limitations

**面试官：** 节点一分钟没心跳，你怎么处理 CAE 任务？

**应覆盖：** 不可达与执行终态分开；保留UNKNOWN与核验策略

**不得主张：** 心跳失败必然进程死亡

**候选人实际发言：** 我先把它标失败释放License，让后面的任务先跑。

**面试官：** 原来的 Solver 其实还在跑，不就超卖了吗？

**应覆盖：** 自然收窄候选人说法；解释不能先释放；主动查询或权威终态

**不得主张：** 继续支持超时直接释放

**候选人实际发言：** 对，我刚才释放说得太早了，要确认执行已经结束。

**面试官：** 你们有 fencing token 吗，PID 校验算不算？

**应覆盖：** 区分进程身份核验和fencing；没有证据不声称已实现

**不得主张：** PID就是fencing；虚构单调token方案已上线

**候选人实际发言：** PID只用于检查是不是目标进程，我不把它等同于栅栏。

**面试官：** 一直无法确认，系统怎样避免永久卡住？

**应覆盖：** 可观察UNKNOWN与超时升级；保留人工/运维处置路径；提出增强是方案不是已有事实

**不得主张：** 无条件杀所有进程；凭空保证自动百分百恢复

## s04 输入预检穿插文件系统边界

**候选人实际发言：** 所以我用输入快照和版本核对，确保一次任务对应确定输入。

**面试官：** 120 组样本怎么设计，46 组都拦下能说明什么？

**应覆盖：** 区分缺陷与合规分布；有限回归证据；设计边界扩展但不伪造原始明细
