# 项目深挖与长场景题

`cases.json` 是 12 题小型高价值场景集，前 6 题构成 smoke，会话按 CAE 深挖 → 连续追问 → Arclight 切换 → 连续追问执行。四道长场景保留完整条件与明确子问题，其中两题超过 1600 汉字，额外覆盖真实的并发时序、取消竞态、资源安全、持久化窗口、权限边界和可重复故障验收；不是重复填充文本来刷长度。其余题覆盖报告版本、对象级鉴权、执行权限、异步协作、跨项目比较和通用问题退出。极速题验证低延迟路径，标准题验证更完整的多子问证据。它不是每项功能都跑一遍的全功能测试集。

题目基于固定 commit 的公开源码自行编写，不冒充网络面试原题。AWS Outbox 文档已实际读取，借鉴其中双写失败时序、重复消息与幂等消费原则。Anthropic 上下文工程文章和 Git 官方 worktree 手册在本次环境返回 HTTP 403，只作为延伸阅读链接；具体断言来自已核对的项目源码。链接与访问状态记录在题集 `references`。

题集只包含公开技术问题、事实卡 ID、源码相对路径和判断规则，没有用户简历、姓名或私人事实正文。将真人材料用于模型评测时，应通过独立的私有输入/报告流程，而不能把这些材料填进公开 CI 样本或完整回答 artifact。源码路径相对各自项目根目录，不能用另一个项目或同项目的随机文件代替。

`expectedFactIds` 是手写相关证据提示，并不要求把所有相关卡全部发给模型；`requiredFactIds` 保留最小硬要求，内容同义组缺失需要复核。`expectedSourcePaths` 是至少一个相关实际源码路径的硬契约，不是由 selector 结果生成。多项目题还需人工核对两个项目各有依据。长题 `subQuestions` 是覆盖核对清单，不能用回答流畅代替逐问覆盖。固定禁止断言仅针对已核实的狭窄错误保证，不能声称自动检查可以穷尽幻觉。

源码边界尤其需要保留：当前 `SharedTaskStore` 使用读取和整文件写入，没有跨进程文件锁/CAS；当前 `Mailbox` 的写入与消费删除没有事务 ACK 或恰好一次保证；`fork` 深拷贝隔离对话内存，`worktree` 隔离工作目录，均不能自动解决这些持久化和合并问题。若个人讲稿与源码存在差异，回答应指出差异并说明建议方案，不能把未实现的防护包装成已有能力。
