针对你提到的直接调用模型 API，以及项目中未显式体现但实际涉及的 RAG 技术，我会这样处理：

关于 API 调用，确实是通过标准接口直接对接大模型，但在工程实现上，我会封装统一的客户端层来管理重试、超时和 Token 计费，确保在高并发下的稳定性，而不是裸调底层 HTTP 请求。

关于 RAG（检索增强生成），虽然代码仓库中可能没有独立的“RAG”模块文件夹，但我会在 Agent 的记忆或知识库查询环节应用其核心机制。具体来说，我会将业务文档切片并存入向量数据库，当用户提问时，先通过 Embedding 召回 Top-K 相关片段，再将其拼接到 Prompt 的上下文中发送给 LLM。比如，在处理供应链库存咨询时，我会先用关键词+向量混合检索找到具体的 SKU 规则文档，再让模型基于这些事实回答，从而减少幻觉并保证数据准确性。
