我会从职责边界和调用机制来区分这三者：Function Call 是模型原生能力，用于结构化输出参数以触发本地工具或API；MCP（Model Context Protocol）是一个开放标准协议，侧重于解耦，让外部服务器以统一方式向模型暴露资源、提示词和工具，解决的是“如何标准化连接上下文”的问题；而 Skill 通常指代应用层封装好的、包含特定逻辑和上下文的复用模块，往往内部已经调用了 Function Call 或 MCP。

具体机制上，Function Call 依赖模型理解 schema 并生成 JSON，由宿主执行；MCP 通过 Client-Server 架构，模型通过协议发现并调用远程工具，适合跨进程或跨服务的复杂集成；Skill 则更像是一个“黑盒”函数，对模型而言可能只是一个简单的入口，但其背后包含了检索、多步推理或特定业务规则的硬编码。

取舍在于：如果只需轻量级本地交互，用 Function Call 最简单直接；如果需要接入第三方生态或隔离敏感数据，MCP 提供了标准化的安全边界和发现机制；如果业务逻辑复杂且需要频繁复用特定工作流，封装成 Skill 能降低模型的认知负担并保证执行一致性。
