我测过 Agent 的任务完成度评估，用的是项目内自建的 benchmark，不是公开榜单跑分。更准确说，针对 Coding Agent 这类任务，我会用固定任务集配合自动判分来测：每条任务有可执行的验收检查，比如代码能跑通、单测通过、改动文件和预期一致；再加一层轨迹检查，看它是否真的调用了目标工具、有没有绕过关键步骤。这样能拿到完成率、单任务平均轮次和失败分布，而不是只看一个总分。

比如一条任务是“修某个函数的边界 bug”，验收就是跑对应单测，全绿算完成，改错文件或单测仍红算失败，超轮次上限算未完成。我的取舍是优先看成功率和失败类型，因为 Coding Agent 分数高低往往取决于任务难度和判分口径；如果要和外部 benchmark 比，我会固定模型、工具版本和最大步数，否则数字不具可比性。项目里具体跑了多少条、什么结果，我按实际数据说话，没测过的维度不报。
