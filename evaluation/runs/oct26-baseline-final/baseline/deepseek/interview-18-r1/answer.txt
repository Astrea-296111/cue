核心做法是别把 50 个工具的完整 Schema 一次性全塞进初始上下文，改成先给模型一份精简的工具目录，按需加载完整定义。

1. 包装层：MCP 进来的工具统一经过 MCPToolWrapper，加上服务名前缀，保留原始 inputSchema，但默认延迟加载，不默认注入。
2. 初始只放目录：首轮只给工具名加一句能力摘要，比如“能读仓库文件”，让模型知道有这个能力，但不把参数 Schema 当可执行定义塞进去。
3. 按需加载：模型通过 ToolSearch 找到相关工具后，再把完整描述和参数 Schema 加载进上下文；摘要只用于发现，真正执行前用的是完整 Schema。
4. 执行校验：真正调用时参数还要过 Pydantic 校验和权限校验，校验不过返回错误结果让模型重试。

这样省的是初始注入这部分。50 个外部工具配置下，初始 Token 从 18.6k 降到 4.2k，大概降了 77%，但这是初始上下文口径，不代表完整任务全程 Token 同比例下降。另外工具搜索本身有选错的风险，我评估时会用明确需求、模糊需求和近似工具三组样本，看工具命中、参数有效和任务完成率，而不是只看 Token 数。
