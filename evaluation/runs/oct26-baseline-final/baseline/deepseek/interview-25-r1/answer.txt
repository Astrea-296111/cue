宏观上可以理解成一条 PNE workflow，但我没做过单 agent 与多 agent 的严格 A/B 实测，不会把简历里的效果说成对照实验结论。我会这样验证：固定同一批任务、同一模型版本和同一评估集，单 agent 组只给一个总控循环，多 agent 组按规划、执行、校验分工；指标看任务成功率、端到端时延、token 成本、失败归因和人工介入率，并记录跨 agent 传参丢失这类具体错误。比如同一条供应链问数任务，单 agent 直接生成 SQL 并自检，多 agent 则由 planner 拆解、executor 查数、checker 复核；如果多 agent 只提升复杂任务成功率、却明显推高时延和成本，我就按任务复杂度做路由，而不是默认多 agent 更好。
