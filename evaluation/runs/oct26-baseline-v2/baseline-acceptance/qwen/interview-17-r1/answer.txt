我会从定位、调用机制和适用场景三个维度来区分这三者。Function Call 是模型原生的结构化输出能力，让 LLM 直接生成符合 JSON Schema 的工具参数，由应用代码执行；MCP（Model Context Protocol）是一个标准化协议，旨在解耦“谁提供工具”和“谁使用工具”，通过 Client-Server 架构动态发现并连接外部数据源或操作接口；而 Skill（通常指 Agent 框架中的技能封装）更多是业务逻辑层面的抽象，可能包含提示词工程、多步编排或特定领域的知识包，不一定对应单一的外部 API 调用。

核心区别在于：Function Call 解决的是“模型如何表达意图”，MCP 解决的是“工具如何被标准化接入和共享”，Skill 解决的是“复杂任务如何被模块化复用”。比如，用 Function Call 可以让模型决定调用 `search_web` 函数，但如果这个搜索功能是通过 MCP Server 提供的，那么任何支持 MCP 的客户端都能自动发现并调用它，无需硬编码集成；而一个“深度研究”Skill 可能内部既用了 MCP 获取数据，又用了 Function Call 进行推理，还包含了固定的分析模板。在实际工程中，我倾向于用 Function Call 做底层交互，用 MCP 做生态互通，用 Skill 做高层业务封装。
