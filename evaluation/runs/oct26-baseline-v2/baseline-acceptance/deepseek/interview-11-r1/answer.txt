我会从控制循环、工具层、上下文管理和安全边界四个层面去理解 Claude Code 这类 Agent 的设计。控制循环是一个“模型决策—工具调用—结果回填”的 while 循环，每轮把工具结果追加进对话再让模型决定下一步，并设最大步数防止空转，比如我前面说的 8 到 15 轮上限，遇到不可恢复异常就直接终止而不是重试。工具层把读文件、改文件、执行命令拆成独立工具，每个工具有明确的输入 schema 和返回结构，文件编辑尽量按片段定位修改而不是整体覆盖，方便审计和回滚。上下文管理上会把大段文件读入和命令输出做截断或摘要，只保留与当前任务相关的部分，避免上下文被撑爆。安全边界上，危险命令和写操作要有确认或白名单，工作目录做隔离，失败分支要返回明确状态而不是假装成功。如果让我自己实现，我会先跑通单 Agent 的最小循环，再加工具注册和步数、异常控制，最后才是多 Agent 分工，这样每一步都能单独验证。
