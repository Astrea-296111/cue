我会从“谁定义接口、谁负责执行、怎么扩展”这三个角度来区分。Function Call 是模型侧的结构化工具调用约定：我先把工具名和 JSON Schema 一起给模型，模型只产出调用意图和参数，真正执行和权限校验仍在我自己的代码里；它偏底层、粒度细，适合查询、计算这类原子操作。

MCP 则是把工具和资源通过标准协议暴露给客户端的开放协议，强调跨应用复用和发现，解决的是“不同客户端怎么接同一套工具服务”，背后可以是本地进程，也可以是远程服务。Skill 更像可复用的任务级能力包，把提示词、步骤、脚本和领域知识打包在一起，模型按需加载，适合“这件事该怎么做”的流程性任务。

所以取舍上：单应用内的原子操作我会直接用 Function Call；要跨多个客户端共享工具，我会包成 MCP Server；要沉淀一套稳定的操作流程或规范，我会做成 Skill，再由它去调用底层工具。比如查订单用 Function Call，把订单查询包成 MCP 给多个 IDE 复用，而“按固定流程排查线上故障”这种就适合写成 Skill。
