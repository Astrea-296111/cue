核心是**不在首轮把 50 个外部 MCP 工具的完整定义全塞进上下文，改成目录加 ToolSearch 按需加载**。18.6K 到 4.2K 是指这 50 个工具配置的初始注入 Token，不是整场任务的累计 Token。

1. 首轮只给模型工具目录。每个工具先暴露服务名、工具名和一段能力摘要，比如“能读仓库文件”，让模型知道有这个能力，但不带完整参数 Schema。
2. 模型判断需要某类能力后，再用 ToolSearch 去检索，命中后把真实工具定义和完整 inputSchema 加载进来，然后执行。这里摘要只用于发现，不能当可执行 Schema 用。
3. 执行阶段该做的校验不省。MCP 工具加服务名前缀包装，参数交给 MCP 客户端；本地工具的 Schema 才由 Pydantic 模型生成，MCP 原始 Schema 是保留的。

这样做的取舍是省了初始上下文，也减少了 50 个工具同时摆在面前的选择干扰，但多了一次发现开销，也有找错工具的风险。所以这个数字只能说明初始注入下降，我会另外看 ToolSearch 的召回、最终工具选对率、参数有效率和任务完成率，全程 Token 也单独算。
